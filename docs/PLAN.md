# Tanks Game – Plan

A browser-based, peer-to-peer, free-for-all tank shooter. The game rules are 2D and the graphics are 3D. It is hosted as static files on GitHub Pages at https://richardyoung.co.za/peertanks/. See [README.md](../README.md) for the original game ideas.

## 1. Decisions so far

| Area | Choice |
|---|---|
| Language / build | TypeScript + Vite |
| Rendering | three.js, tilted top-down perspective camera (not true isometric) |
| Art style | Stylised low-poly, flat-shaded. Tanks, trees and rocks are all built in code; we keep this look rather than switching to detailed models |
| Physics | Rapier 2D (`@dimforge/rapier2d-compat`, WASM) |
| Networking | PeerJS (WebRTC) for connecting, plus our own fast data channel; host is authoritative |
| Maps | Tiled JSON files |
| Gameplay tuning | One compile-time config file holding every balance number |
| Players | Up to 8 per game, humans and bots combined |
| Host leaves | Game ends for everyone (no host migration in v1) |
| NAT / TURN | Public STUN only for now (see §3) |
| Assets and licensing | Royalty-free **and** attribution-free by default: CC0/public-domain assets, or generated by free local models whose output carries no terms. Anything with other terms (e.g. ElevenLabs, CC-BY packs) only after asking |
| Announcer voice | Generated once with a free local text-to-speech model (e.g. Kokoro, Apache-2.0) and committed as audio files |

## 2. Architecture

Three layers that only talk through plain data:

```
 input ──► Simulation (pure TS + Rapier) ──► ViewState ──► Renderer (three.js)
 bots  ──►          ▲            │                          UI (HTML/CSS)
                    │            ▼                          Audio
                Network (host / client)
```

- **Simulation** has no three.js or DOM code. The host runs it as the source of truth. Clients run a small copy of it to predict their own tank's movement.
- **Bots** run on the host and produce the same `PlayerInput` a human would. The simulation can't tell them apart, so bots can't cheat by reaching into game state they "shouldn't see".
- **Renderer** draws a plain `ViewState` (positions already interpolated). Host and clients build it differently, but the renderer is shared.
- **UI** is an HTML/CSS layer over the canvas (menus, HUD, scoreboard).

## 3. Networking

**Joining**
- The host's PeerJS ID is `peertanks-<CODE>`, where CODE is 6 characters with no ambiguous letters (no O/0, I/1). The prefix never changes, so any two builds can find each other and run the version check below.
- The invite link is `…/peertanks/#join=<CODE>`. Every player sees the code and a *Copy link* button in a slim bar in the top-left corner. After joining, the address bar also shows the link.
- People can join from the lobby or mid-game.

**Version check**
- Every build is stamped with its version (from `package.json`), git commit and commit time. The build label shows small in the bottom-right corner.
- The joining player sends their build with the join request, and the host compares commit times:
  - **Joiner older:** turned away with a message explaining how to do a hard refresh.
  - **Host older:** the joiner is turned away and told to ask the host to refresh. The host gets a dismissible warning.
  - **Same:** joins normally.
- The join request and the rejection reply must keep the same shape forever, so even very old and very new builds can tell each other they don't match.

**Data flow**
- Clients send **inputs** every tick (60 per second), repeating the last 3 in each packet in case one is lost.
- **Two channels per player:** PeerJS's reliable channel carries the welcome, join/leave, events and pings. A "fast" channel we open ourselves never resends lost packets, and carries inputs and snapshots. The host only sends on it once the client has sent something, which avoids a start-up race that could break the connection.
- The host sends **snapshots** 20 times a second, in compact binary: about 13 bytes per tank and 10 per projectile. With 7 clients the host uploads roughly 45 KB/s.
- The host sends the whole map in the welcome message, so players can join games on maps they don't have.
- **Disconnects** are picked up early: closing the tab closes the connection properly. Otherwise a player silent for 5 s is dropped, and a client with no snapshots for 5 s sees "lost connection".
- **Frozen tabs:** if a page freezes for seconds (e.g. compiling graphics on a slow machine), the next silence check is skipped instead of blaming the network. Joining players also get 15 s before the host gives up on them.
- **Background tabs:** a worker keeps the simulation ticking while the tab is hidden. A client that goes quiet is treated as idle after 0.25 s, so its tank stops driving.

**Smoothness**
- **Own tank:** moves instantly (prediction), then is quietly corrected by replaying inputs the host hasn't processed yet.
- **Other tanks:** drawn about 100 ms behind real time, blended smoothly between snapshots.
- **Own shots:** recoil and muzzle flash are instant. **To do:** draw a predicted shell straight away too, since on a laggy connection the real one currently appears slightly behind a moving tank.
- **Events** (hits, shots) play in time with the delayed view, so effects line up with what you see.

**NAT / connection problems**
- **TURN status (Oct 2026):** the free no-signup relays (PeerJS's own, Open Relay static auth) are offline, so there is no relay. Direct connections via STUN cover most home networks. If players on strict networks can't connect, add ExpressTURN (1,000 GB/month free) or Metered (20 GB/month, ports 80/443 + TLS). Both need a free signup, and credentials would come from `.env` or a GitHub Actions secret at build time.
- **Known limitation:** Firefox only uses the network interface behind the default route. On a Mac whose default route goes through a VPN-style interface, Firefox finds no usable address and can't connect. Firefox on other machines is fine.
- Trystero stays the fallback if the PeerJS public signalling server becomes unreliable.

## 4. Gameplay

### Gameplay config file

`src/gameplay-config.ts` is one typed file holding every number that affects balance. It's read at build time, so changing it means a rebuild, not a live setting. It covers:
- **Tanks:** speed, acceleration, health, radius.
- **Each weapon:** damage, projectile speed, fire rate, ammo, bounces, splash radius and splash damage, knockback.
- **Each powerup:** strength and duration.
- **Death and respawn:** respawn delay, invulnerability time.
- **Rounds:** default length, results screen time.
- **Pickups:** default spawn interval.
- **Bots:** the skill bounds for easy, medium and hard (see §5).

### Movement, aim and terrain

- **Movement:** arrows/WASD move the tank relative to the screen. The hull turns to face the travel direction (front or back, whichever is closer). Tanks are dynamic physics bodies: they slide along walls, push each other and can be knocked back.
- **Aim:** the turret points at the mouse position on the ground.

| Terrain | Blocks tanks | Blocks direct shots | Kills tank |
|---|---|---|---|
| floor | – | – | – |
| wall / rock | ✔ | ✔ (bounces off) | – |
| tree | ✔ | ✔ | – |
| water / lava / pit | – | – | ✔ |
| arena edge | ✔ | ✔ (bounces off) | – |

Mortars and thrown grenades fly over terrain.

- **Health:** 100. Killed tanks respawn after 3 s at the spawn point furthest from enemies, then are invulnerable for 2 s. A kill scores +1.
- **Explosions:** full damage inside an inner radius (enough to kill), falling off to zero at an outer radius. They push tanks outwards, so a near miss can still shove you into lava.
- **Physics that adds to gameplay:** recoil on heavy weapons; tanks bump rather than stopping dead; grenades bounce and roll with friction. Knockback is decided on the host, so it's fair.

### Weapons (starting values, all in the config file)

| Weapon | Behaviour | Damage | Ammo |
|---|---|---|---|
| Cannon (default) | Slow straight shot, gone on any hit | 10 (10 shots to kill) | Unlimited |
| Machine gun | Rapid fire, small spread | 4 | 60 |
| Bouncy cannon | Straight shot, bounces 3 times | 25 | 10 |
| Laser | Instant, reflects 3 times, beam effect | 40 | 5 |
| Rocket | Fast straight shot, explodes on contact | 100 inner / falloff | 4 |
| Grenade | **Hold the mouse button to charge the throw (up to 3 s = furthest).** Hard throws arc high enough to sail over walls and trees; then it rolls and bounces, 2 s fuse. A charge bar shows under your name tag, but there's no landing hint: judging the throw is part of the skill | 100 inner / falloff | 3 |
| Mortar | High arc to the cursor spot, flies over terrain. The shooter sees a target ring; nobody gets a danger-zone warning | 100 inner / falloff | 3 |

- **Switching weapons:** keys 1–7 or the mouse wheel. Cannon is always slot 1.
- **Cooldowns:** each weapon has its own minimum time between shots, longer for stronger weapons (machine gun 0.08 s up to mortar 2 s). Switching weapons doesn't reset them. No visual indicator.
- **Own explosions hurt you** at full damage; a self-kill is a death with nobody scoring. Ricochets and lasers can hit you after their first bounce.
- **Dying loses all collected weapons.** Picking up a weapon you don't have switches to it; one you already have just adds ammo (up to two pickups' worth).

### Powerups (starting values, all in the config file)

An active powerup shows on the tank, so other players can see it.

| Powerup | Effect | Duration |
|---|---|---|
| Shield | Take 50% less damage | 20 s |
| Speed | Move 40% faster | 10 s |
| Damage boost | Deal 50% more damage | 10 s |
| Dead man's switch | Explode on death, causing rocket-like splash damage | Until death or 30 s |

### Pickups

- Weapons and powerups appear at **spots placed in the map**, as small floating models of the item itself. There are no labels, and nothing marks an empty spot.
- A spot fills again a set time after it's collected; the time comes from the map, or the config default.
- Each spot either picks randomly from **everything**, or from a **subset** listed in the map, e.g. "rocket, grenade, mortar" for a heavy-weapons spot.
- The host's allowed list (see §7) filters this further: a disabled weapon never spawns. A spot whose whole subset is disabled stays empty.

### Rounds and score

- Free-for-all. Default 3 minutes; the host can change this in the lobby. The highest score wins, a results screen shows for 20 s, then the next round starts.
- Players can join or leave at any time. Leaving and rejoining resets the score.
- **Scoreboard (always visible, top-right):** a compact list of everyone in the round, bots included, with kills, deaths, kill/death ratio and any current kill streak. It sits under the ping bar and stays narrow, so the middle of the screen stays clear.

## 5. AI bots

Bots can be added in the lobby, or added and kicked from the host's in-game menu. The host picks **easy, medium or hard**. Each bot also gets a random **play style** (archetype), plus random variation on every value, so two "medium" bots don't play the same. Bots run only on the host and send the same input a human would.

**What makes them feel human** (from research into the Quake III and Counter-Strike bots, the BotPrize "Turing test for bots" and the "Artificial Stupidity" talk):
- **Keyboard-like driving:** only the 8 WASD directions, each held for at least 0.15 s. Smooth analogue movement is the quickest giveaway.
- **Mouse-like aim:** the turret swings onto the target like a spring, overshooting when rushed. The aim error drifts slowly instead of jittering, starts large on a new target and shrinks while tracking.
- **Reaction time:** a new enemy or incoming shot only registers after the bot's reaction time (humans take about 0.2–0.35 s).
- **Plausible mistakes:** hesitating, wasted shots, imperfect leading, dodging the wrong way, now and then not watching the edge of the water.
- **No repetition:** random wander spots, routes and decisions, because BotPrize judges spotted bots within minutes from repeated paths.
- **Fair play:** easy and medium bots won't join in on a human already fighting 2 bots. Hard bots ignore this.

**How they work** (`src/bots/`):
- **Perception:** a bot sees roughly one screen around itself, like a player (whose top-down view shows tanks behind walls too). It remembers enemies for 4 s after they leave view, and learns roughly where an attacker is when hit. It only knows what's in a pickup spot if it has seen it.
- **Decisions (utility AI):** about 10 times a second the bot scores fight, chase, collect pickup, retreat to cover and wander, then picks the best. Its personality weights the scores, and the current plan gets a bonus so it doesn't flicker between choices.
- **Navigation:** A* on the tile grid. Hazards are never stepped on, and tiles beside them cost extra, more so for careful bots. Routes cut corners where a straight line is clear. A look-ahead check stops the bot driving into water.
- **Shooting:** leads moving targets, picks the weapon for the range and situation, charges grenades for the right distance, lobs mortars over cover, and finds bank shots off walls for the laser and bouncy cannon.

**Personality** (all bounds in `GAMEPLAY.bots` in the config file):

| Skill (set by level) | Style (set by archetype) |
|---|---|
| Reaction time, aim error, aim speed and overshoot, leading, dodging, hazard awareness, trigger discipline, hesitation, trick-shot limit | Aggression, caution (retreat health), pickup greed, vengefulness, trick-shot keenness, preferred range |

| Archetype | Plays like |
|---|---|
| Brawler | Charges in, fights up close, holds grudges, rarely retreats |
| Sentry | Holds back near cover, fights from range, retreats early |
| Scavenger | Goes far for pickups, loves powerups |
| Trickster | Prefers bounce shots, lasers off walls and lobs over cover |
| All-rounder | Middle of the road |

Bots get tank-themed names and colours like players, show a small level-coloured **Bot** badge on the scoreboard and in the player lists, and count towards the 8-player limit.

## 6. Maps

- Authored in Tiled with two layers:
  - **terrain:** a tile layer. Each tile has a `terrain` property (see the table in §4) and an optional `variant` that forces a particular tree or rock shape.
  - **objects:** spawn points and pickup spots. A pickup spot can have `items` (the subset to choose from; empty means everything) and `respawnSeconds`.
- One map is one self-contained `.json` file, so maps can be shared. The game turns tile types into 3D models.
- Maps are checked when they load (spawns exist, size within limits, tile types known).
- Maps so far: "Meadow" (28×20, small) and "Crossroads" (36×26, medium: a river with three bridges). New maps are listed in `public/maps/index.json`.
- Changing map between rounds replaces the host's world, and everyone gets a fresh welcome for the new map. The tick count carries on, so leftover messages from the old map are ignored.
- **Themes:** each map has a `theme` (now `grassland`; later e.g. snow, lava, jungle). The theme sets the palette and which shapes are used for each tile type. A tree is a pine in snow and a palm in the jungle, but behaves the same in the game. A new theme should only need a theme file.

## 7. Menus and UI

- **Main menu:** name (saved in `localStorage`), *Host a game*, *Join* with a code box.
- **Look:** chunky, toy-like slabs in the arena's own colours, with buttons that press down. Headings use *Lilita One* and text uses *Barlow Semi Condensed*; both are free fonts (Open Font License), bundled with the game. The lobby and menu are laid out to fit a laptop screen with no scrolling.
- **Host lobby** (before the first round). The invite link is already live here, and joining players appear in the lobby. The host sets:
  - the **map rotation**: one or more maps, shown as cards with a rendered thumbnail and an S/M/L size badge. Rounds play the picked maps in turn, and the results screen says which map is next
  - which weapons and powerups are allowed, as tiles with rendered pictures (this filters what spawns)
  - the round length, as pill buttons
  - bots to add (easy/medium/hard)
  - *Start* to begin
- **In-game menu (host),** opened with Esc (the game carries on behind it):
  - change round length and allowed items, applied from the next round
  - kick players, including bots
  - add bots of any level
  - end the game, which sends everyone back to the menu
  - the map rotation can be changed too; the new order takes over after the current round
- **In-game menu (others):** the same players and settings, read-only, plus *Leave game* (and volume settings once there's audio).
- **Controls guide** (keycaps for drive, aim, fire, charge, weapons, menu) in the lobby and the in-game menu. It isn't shown on screen during play, so the weapon bar sits at the bottom edge.
- **Thumbnails** are rendered from the game's own 3D models when menus first load, so they always match the current look and need no image files.
- **HUD:**
  - slim invite bar (top-left) and ping bar (top-right)
  - scoreboard under the ping bar
  - health bar, current weapon and ammo, weapon slots
  - round timer
  - event feed (bottom-left): kills, plus players joining and leaving
- **End of round:** results with the winner.

## 8. Rendering and visuals

- **Camera:** tilted ~55°, following your tank so it stays centred. While you're dead it holds still, then snaps to your respawn point. No minimap.
- **Tanks:** low-poly, built in code and tinted in each player's colour. Tracks animate as they move. Each weapon gets its own barrel shape.
- **Name tags:** each tank shows its player's name and health bar.
- **Lighting:** one sun with soft shadows plus ambient light, and a soft bloom glow on the brightest things (lava cracks, sparks, flames, lasers, muzzle flashes). Only colours brighter than white glow, so the flat-shaded look stays crisp.
- **Graphics setting:** High / Low, on the main menu and in the Esc menu, saved in the browser. Low turns off shadows and bloom, draws at one pixel per screen pixel, and halves the particles.

### Terrain look (low-poly, with variety)

- **Trees:** five shapes (pine, round leafy, tall conifer, bush cluster, the odd dead tree), each with random rotation, size, lean and shade. Every shape stands taller than a tank's barrel, because trees block shots.
- **Rocks:** four shapes (boulder, cluster of 2–3, flat slab, mossy boulder).
- **Floor:** a soft checkerboard with per-tile colour variation and drifting patches of bare ground and lush grass. There are no scattered decorations: grass tufts, flowers and pebbles were tried and looked out of place.
- **Themes and variants:** the theme sets which shapes appear and how often. A map tile can force one with a `variant` property next to its `terrain` (e.g. terrain=tree, variant=round).
- **Water:** one continuous low-poly surface with gentle waves, colour that deepens away from the shore, ripples, sun glints, a broken foam line, and see-through shallows over a sandy bank.
- **Lava:** a slowly flowing dark crust with thin glowing cracks, a pulsing glow that's brightest at the edge, bubbles that swell and pop, embers rising, and a slight warm tint on nearby ground.
- **Shorelines:** a smoothed "distance into the liquid" field gives rounded coastlines and a sloped bank (grass → sand → bed for water; grass → scorched ground → thin dark rim for lava). Pits stay square holes.
- **Fairness rule:** the bank starts exactly at the hazard tile's edge, so the visible waterline is always inside the hazard tile.

### Hazard edges

A tank only falls in once its centre is a little way past the edge (`GAMEPLAY.hazardEdgeAllowance`: a quarter of a tile for water and lava, roughly where the waterline is drawn; less for pits). Clipping a corner over the water is safe.

### Effects

- muzzle flash, recoil, squash-and-stretch on firing and hits, shimmering shield while invulnerable
- **Trails:** a glowing streak behind shells and bullets, smoke and flame behind rockets, puffs behind mortar shells and thrown grenades, a sparkle trail on bouncy shots
- **Explosions:** fireball and shockwave, flames, sparks, bouncing debris, soft smoke, screen shake, and a scorch mark that fades after a few seconds (not on water or lava)
- **Destroyed tanks:** a burst of flame and debris, the turret flies off spinning and bounces, the hull is left burnt and smoking, then sinks away
- **Hazard deaths:** the tank tips over the edge it went off, then sinks with a splash and bubbles (water), chars, glows red-hot and melts with smoke and sparks (lava), or tumbles away shrinking (pit)
- particles are shared pools of instanced meshes, so effects stay cheap
- **Not planned for now:** floating damage numbers (decided against), tank wobble on bumps, barrel droop while reloading

## 9. Audio and assets

### Licensing rule

Keep licensing simple: everything shipped in the game must be **free to use without royalties or attribution**.
1. **First choice:** CC0 / public-domain assets (e.g. Kenney packs, CC0-tagged Freesound sounds), or things we generate in code (tanks, trees, rocks and most effects already are).
2. **Second choice:** generate it with a **free local model** whose licence puts no conditions on the output. For each model, check that both the model and its voices or weights allow this.
3. **Only if neither works:** ask first before using anything with other terms, such as ElevenLabs (non-commercial plus attribution on the free tier), CC-BY packs that need credits, or paid services.

Each asset's source and licence is recorded in an `ASSETS.md` file, so it's easy to check later.

### Sound effects and announcer

- **Sound effects:** CC0 sounds, played through the Web Audio API, with volume set by distance from your tank.
- **Announcer:**
  - The lines include round start, final 30 seconds, round over, first blood, double kill, killing spree and you win, plus fun voice prompts when someone is killed. There are several variants per event, so they don't get repetitive. The script lives in `tools/voice-lines.json`.
  - `npm run voice` generates any new or changed lines with a local text-to-speech model. **Kokoro** (Apache-2.0) is the first candidate, with voice licences checked before use.
  - If local voices aren't good enough for a fun announcer, I'll ask before switching to ElevenLabs. The API key in `.env` stays unused until then, and if used it would never go into the game.
- Volume sliders, saved in `localStorage`.

## 10. Deployment

- A GitHub Actions workflow builds with Vite and publishes to GitHub Pages on every push to `main`. The build uses relative paths, so it works under `/peertanks/` and the custom domain.

## 12. Risks

- **PeerJS public signalling server** can be rate-limited or go down. Trystero is the fallback.
- **No TURN relay:** players on strict networks can't connect. They get a clear error, and a relay can be added later.
- **Rapier WASM** makes the first download about 1.5 MB (gzipped). It's cached after that.
- **Host performance:** the host simulates (including bots) and renders. Fine for 8 tanks, but worth watching on low-end laptops.
- **Smooth shorelines:** the visuals must not mislead players about where hazards start (see the fairness rule in §8).
